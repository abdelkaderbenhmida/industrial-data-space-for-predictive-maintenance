Problem Statement

  • Factories have valuable IoT sensor data for predictive maintenance
  • Companies reluctant to share sensitive industrial data
  • Need collaborative ML without data centralization

Solution: Industrial Data Space

Federated Learning (Flower/FedAvg) — train locally, aggregate weights
Data Space (EDC) — sovereign data exchange, contracts, policies
IoT Simulation — realistic sensor data with anomalies
Dashboard — real-time monitoring, alerts, metrics

Module 1: IoT Simulation

  • 3 factories with distinct sensor profiles
  • 5 sensors: temperature, vibrations, pressure, humidity, power
  • Realistic: drift, noise, anomalies (8%), failures (3%)
  • Local CSV storage per factory/date
  • MQTT publishing to broker

Module 2: Data Space (EDC)

  • 3 EDC connectors (ports 8080, 8081, 8082)
  • Asset publishing: 5 sensor datasets per factory
  • Access policies: consumer allow-lists
  • Contract negotiation: request → confirm → data access
  • Exchange logging: full audit trail
  • Discovery: connector registry

Module 3: Federated Learning

  • Flower server: FedAvg, 5 rounds, min 3 clients
  • Model: TF/Keras MLP (5→64→32→16→1, sigmoid)
  • Binary classification: normal vs failure
  • Local training: 1 epoch per round
  • Metrics persisted: accuracy, precision, recall, F1
  • Model checkpoints per round

Module 4: Kubernetes Deployment

  • 9 YAML manifests
  • Namespace, ConfigMap, MQTT broker
  • 3 IoT factory deployments
  • 3 ML client deployments
  • 3 EDC connector deployments
  • Flower server + Dashboard deployments

Module 5: Dashboard

  • Streamlit UI (port 8501)
  • FastAPI backend (port 8000) with Swagger
  • Real-time sensor charts (Plotly)
  • FL metrics: accuracy, precision, recall, F1 per round
  • Maintenance alerts with severity
  • Factory connection status
